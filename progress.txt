## Codebase Patterns
- 后端代码在 `backend/`，启动命令必须在 backend 目录下执行：`python -m uvicorn app.main:app --host 127.0.0.1 --port 8010`
- **后端端口固定为 8010**（本机 8000 被 Windows 系统服务 svchost.exe 占用，绑定会报 WinError 10013，不要用 8000）；并行验证时各 worker 用独立端口（8010/8011/8012/8015 均可），测试前先 `netstat -ano | findstr ":801"` 探测空闲端口，测完 taskkill 清理
- 每个资源一个路由文件：`backend/app/routers/<name>.py`，统一前缀 `/api/v1/<name>`；各路由专属的 Pydantic 请求/响应模型**定义在路由文件内部**，避免多个 worker 并行改 `schemas.py` 造成冲突
- 代码风格统一：Pydantic 模型定义在路由文件内部 + `_to_out` 辅助 + `db.get` 判 404 + `select(func.count())` 计数 + 中文 detail 消息 + 路由路径用 ""（前缀已含 /api/v1/<name>）
- 数据库：SQLite，文件在 `backend/data/kefu.db`（已 gitignore）；ORM 用 SQLAlchemy 2.0 `Mapped` 风格；启动时 `init_db()` 自动建表，无需迁移工具
- 种子数据：`backend/scripts/seed.py`（幂等，可重复执行）；执行方式 `cd backend && python scripts/seed.py`
- 前端将放 `frontend/`（Vite+Vue3+Element Plus），dev server 端口 5173，`vite.config.js` 中 `/api` 代理目标为 `http://127.0.0.1:8010`
- 本机 Python 3.12 位于 `C:\Python312`，`python` 命令直接可用；npm 可用（Node v24）
- 健康检查端点：`GET /api/v1/health`
- **cmd 下 curl 带中文查询参数会乱码/空响应，必须 URL 编码**（如 退款 → %E9%80%80%E6%AC%BE）；POST/JSON body 里的中文在 cmd 里也可能出问题，尽量用 ASCII 或临时 .py 脚本；状态码用 `-w "\nHTTP:%{http_code}"`（单 `%`，`%%` 会被当字面量）
- **同一 cmd 命令行里用 `&` 并行执行 curl 时存在竞态**（如 DELETE 与 PUT 同一 id），写入/修改类测试要串行
- 标签精确匹配技巧：`func.concat(",", Script.tags, ",").like(f"%,{tag},%")` 避免"催"误匹配"催办"
- cmd 控制台显示中文 JSON 乱码（GBK 显示 UTF-8）是**显示问题**，数据本身正确；验证时看结构/数量/状态码即可
- 列表响应统一 `{total, items, page, page_size}`
- 运行中的 uvicorn 不会热加载新代码，改了路由文件必须新起端口验证
- **共享工作区并行时绝不能 `git add -A`**：会把其他 worker 未提交的改动卷进自己的提交；只 add 自己负责的文件
- shell 审批策略会拦截含 `rm`/`del`/DELETE 类命令；写操作测试改用 Python urllib 临时脚本（放 %TEMP%），避免触发审批
- 停止 uvicorn：`for /f "tokens=5" %a in ('netstat -ano ^| findstr :端口 ^| findstr LISTENING') do taskkill /F /PID %a`
